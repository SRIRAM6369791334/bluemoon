# Bluemoon Crackers - Lessons Learned

## [UI_Bugs]
- **Duplicate Headers in Accordion Footers:** When Bootstrap collapsible accordions (`widget-collapsed-title`) are used in footers for mobile screens, ensure the static desktop headers (`widget-title`) are explicitly hidden via `@media (max-width: 767px) { display: none !important; }`. Otherwise, users see duplicate headers above each accordion toggle on mobile.
- **Floating Overlap on Mobile Screens:** Fixed-position elements (like social icons and quick order badges) take up huge percentages of horizontal screen space on 360px-390px mobile screens. They must be scaled down (e.g. 40px WhatsApp, 65px Quick Order badge) and placed at bottom corners, with secondary social links moved to the offcanvas menu and footer.
- **Swiper Responsive Breakpoints:** In SwiperJS, setting `slidesPerView: 1` on mobile for e-commerce products results in bloated single cards. Setting `slidesPerView: 2` with `spaceBetween: 10` provides the familiar, dense e-commerce card grid that users expect on mobile devices.
- **Strict Media Query Scoping for Zero Desktop Regressions:** When modifying Blade templates shared across devices, never alter global un-scoped class definitions. Always encapsulate mobile adaptations strictly inside `@media (max-width: 767px)` or use Bootstrap responsive utility classes (such as `col-6 col-md-6 col-lg-3`).
- [UI_Bugs]
- **Fixed Table Row Height Traps in Legacy CSS:** Legacy stylesheets (like `style.css` in e-commerce themes) often contain rules like `.shopping-cart-form .table tbody tr { height: 74px; }`. When transforming a table into stacked cards with CSS Grid or Block layout on mobile, failing to explicitly override `height: auto !important` and `min-height: auto !important` causes all card content beyond 74px to be clipped or overlap adjacent cards. Always check for inherited fixed heights when doing table-to-card transformations.
- **Sticky Fixed Action Bar Colliding with Offcanvas Drawers:** When using a `position: fixed; z-index: 9999;` sticky bottom action bar (like a bottom checkout button), it floats on top of Bootstrap offcanvas drawers (`z-index: 1045`), obscuring primary modal action buttons such as "Confirm Estimate". Always hide the fixed bottom bar via CSS (`body.offcanvas-open #checkout-bar { display: none !important; }`) and attach Bootstrap `show.bs.offcanvas`/`hidden.bs.offcanvas` event listeners to toggle visibility.
- **Absolute Remove Icon Collision with Fluid Titles:** In offcanvas list items, placing an absolute-positioned remove icon (`.remove`) at `right: 0` without right-padding on the parent or title causes multi-line product names to overlap the remove icon. Adding `padding-right: 32px` on the link container and styling the remove icon as a discrete circular badge ensures no visual collisions.

## [Logic_Flaw]
- **Float vs CSS Grid for Table Cell Card Transformations:** Converting `<tr>` elements to stacked cards via CSS `float` often causes float containment and clearing bugs because internal table cell layout engines do not guarantee proper clearance. Converting `<tr>` to `display: grid` with explicit `grid-template-columns` and `nth-child` row/column assignments guarantees reliable, deterministic multi-row card layouts on mobile.
- **Static Hardcoded Section IDs in Dynamic Catalogs:** Hardcoding section IDs like `whereIn('id', [1, 2, 3])` in Blade views breaks CMS/Admin dynamic section additions. Newly created sections in admin panels get higher IDs and never render on the frontend. Use dynamic queries with exclusionary filters (e.g., `where('id', '!=', 5)->orderBy('id')`) and guard with `@if($sectionproducts->count() > 0)` to ensure only populated sections appear.
- **Hardcoded Input IDs in Checkbox Label Loops:** In blade loops generating custom checkboxes (`custom-control-input`), hardcoding `for="customCheck2"` on `<label>` causes every item's click event to target Product ID 2. Since Bootstrap hides raw inputs (`opacity: 0`), users clicking product names repeatedly toggle the wrong product. Always match `for="customCheck{{ $pro->id }}"` with `id="customCheck{{ $pro->id }}"`.
